# 看板发布前 1,000 次迭代

标题右侧自动显示当前上线版本的迭代数、目标进度和最近8次提交；点击可展开口径与记录。
从基线 `b88fba16c13163ac8c56f74109f70fe549df4abf` 之后开始，不估算历史次数。

- 一个涉及看板产品/数据包/运行构建的非merge Git提交计1次，改一个字也算。多处修改同一提交计1次。
- 路径范围在 `build/iteration-history.mjs`：app/public/worker/build/scripts/ops及列明的运行配置。
- 纯docs/tests/AGENTS更改不计数。合并提交本身不重复加数，分支内独立提交分别计数；revert属于新改动计1次。
- 构建时从Git历史生成只读常量，随服务器和客户端同一构建发布；无浏览器localStorage计数、手动+1接口或访问量计数。
- 刷新、重启、相同版本重复部署不增加。未发布的提交不会出现在线上；失败构建不应被启动。
- 本计数是当前发布版本包含的改动数，不是跨版本部署日志；回滚到旧版本时显示旧版本的次数。
- 超过1000仍显示真实次数，进度条封顶100%。基线不存在/浅克隆历史不足时构建报错，不静默归零。
- 一个独立改动请单独提交，提交标题写清实际改动；不能按行数、保存次数或文件数冒充独立迭代。
- Git外部动态数据/媒体原地变更不可自动识别；应遵循现有不可变数据包规范，提交对应版本/来源更新后发布。

不需要维护数字文件。正常工作树开发、提交、合入干净main并按 `ops/4090/update.sh` 发布即可。
本功能不更改评测数值、指标聚合、登录鉴权或发布门禁。
